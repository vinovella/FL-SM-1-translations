# Dutch localization Phase 0 workspace

This directory contains the concrete Phase 0 baseline, inventory and language-contract work for the Dutch SM-1 localization.

Phase 0 is intentionally separate from translation implementation. No Dutch `.rpy` translation tree is created here; that belongs to Phase 1 after the language contract is confirmed.

## Phase 0 deliverables

| Deliverable | File | Status |
| --- | --- | --- |
| Baseline and inventory method | `PHASE0_BASELINE.md` | Complete |
| Candidate `.rpy` manifest | `PHASE0_FILE_MANIFEST.csv` | Generated by workflow |
| Inventory summary | `PHASE0_INVENTORY_SUMMARY.md` | Generated by workflow |

| Automated generation/check | `../../.github/workflows/dutch-phase0-inventory.yml` | Complete |

## Exit criteria

Phase 0 is complete only when all of the following are true:

- [ ] Ren'Py runtime language key is confirmed by an SM-1 maintainer.
- [ ] Displayed Dutch language name is confirmed by an SM-1 maintainer.
- [ ] Dutch storefront JSON scope is confirmed by an SM-1 maintainer.
- [ ] `PHASE0_FILE_MANIFEST.csv` has been generated from the pinned baseline.
- [ ] The manifest has zero `Unassigned` phase values.
- [ ] Every candidate `.rpy` path represented by the configured production language trees appears in the manifest.
- [x] Initial glossary and character-name policy are documented.
- [x] Initial Netherlands-Dutch style guide is documented.
- [x] Exception/unchanged-string policy is documented.

The first three items are deliberately not guessed. Existing repository conventions support the proposals recorded in `PHASE0_EXTERNAL_CONFIRMATIONS.md`, but repository convention is not the same thing as maintainer confirmation. Humans invented project-specific identifiers, so naturally another human has to confirm them.
